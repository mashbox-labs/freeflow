# Free Flow

Free Flow by MASHBOX Labs is free, on-device voice dictation for iPhone, iPad and Mac.

Hold a key and talk. When you let go, your words go in where your cursor is. Speech recognition and text cleanup run on your device. 100% private: nothing you say leaves your device.

- iPhone and iPad: a keyboard extension with a mic key, plus a Start/Stop control for Control Center, the Lock Screen and the Action Button. iOS 18 and iPadOS 18 or later.
- Mac: hold fn in any app and talk. Press fn twice for hands-free, Esc to cancel. A menu bar item and a small pill show the state. macOS 15 or later, Apple silicon.
- One dictionary for names and words spelled your way, and a history of what you dictated.
- Writing styles (formal, casual, very casual) when Apple Intelligence is on; otherwise the text goes in as heard.

No account, no analytics, no ads, no crash reporting. The only network use is downloading the speech model files you pick, from Hugging Face, at revisions pinned in the app.

## Repository layout

| Path | What it is |
|---|---|
| `App/` | The iPhone and iPad app (SwiftUI). The Mac app is this app built for Mac Catalyst. |
| `Keyboard/` | The keyboard extension. |
| `Widgets/` | Control Center, Lock Screen and widget controls. |
| `Catalyst/`, `MacBridge/` | The Mac build: Catalyst-only screens and an AppKit plug-in for the fn key, paste at the cursor, the menu bar item and the pill. |
| `Mac/` | An earlier native AppKit version of the Mac app, and the files the plug-in shares with it (fn monitor, paste, audio devices). |
| `Packages/FreeFlowKit` | Shared code: dictation session, keyboard geometry, history, dictionary, styles, theme, the speech model catalog. |
| `Packages/FreeFlowEngine` | The C++ speech engine: a thin C shim over llama.cpp and whisper.cpp, shipped as an xcframework that `scripts/build-engine.sh` builds from pinned sources. |
| `Packages/FreeFlowRules`, `Packages/FreeFlowTagger` | Text formatting helpers and a small on-device disfluency tagger (Core ML). |
| `Packages/FluidAudio`, `Packages/WhisperKit` | Vendored copies of FluidAudio and WhisperKit at pinned versions, unchanged, with their licences. |
| `ThirdParty/WordList` | The keyboard's autocorrect word list and the notices of the lists it is made from. |
| `ThirdParty/Models`, `ThirdParty/LoaderArt` | The makers' notice files for the Bark models, and the notices for the font and renderer behind the first-launch loader. |
| `Configuration/` | Build settings. `Base.xcconfig` is committed; `Local.xcconfig` holds your team and bundle prefix and is git-ignored. |
| `scripts/` | Project generators, the engine build, the model manifest, the word list build, release scripts. |
| `tools/keys/` | The tap simulator and geometry solver behind the keyboard layouts, with the sources each number comes from. |
| `UITests/`, `Packages/*/Tests` | UI tests and unit tests. |

`FreeFlow.xcodeproj` (iPhone and iPad) and `FreeFlowCatalyst.xcodeproj` (Mac) are generated by `scripts/generate-project.py` and `scripts/generate-catalyst-project.py` and committed. Edit the generator, not the project file.

## Building

You need Xcode 27 on Apple silicon, and CMake (`brew install cmake`) for the engine.

1. Copy the signing template and fill it in. For a simulator build you can leave `DEVELOPMENT_TEAM` empty.

       cp Configuration/Local.xcconfig.template Configuration/Local.xcconfig

   `FF_BUNDLE_PREFIX` becomes the prefix of every bundle identifier (`<prefix>.freeflow`, `<prefix>.freeflow.keyboard`, and so on) and of the App Group. `DEVELOPMENT_TEAM` is your Apple Developer team. Nothing else about signing lives in the repository.

2. Build the speech engine once. It clones llama.cpp and whisper.cpp at the pinned commits, builds the static libraries for iOS, the simulator, macOS and Mac Catalyst, and writes `Packages/FreeFlowEngine/FreeFlowSpeech.xcframework`. It takes a while.

       scripts/build-engine.sh ios sim mac catalyst
       scripts/build-engine.sh --check

   `--check` compares the result with the committed sha256 list, which was recorded with Xcode 27.1. A different Xcode can give different bytes; the app still builds.

3. Open `FreeFlow.xcodeproj` and run the `FreeFlow` scheme on an iPhone or iPad simulator, or open `FreeFlowCatalyst.xcodeproj` and run the `FreeFlowMac` scheme on your Mac.

   From the command line, without signing:

       xcodebuild -project FreeFlow.xcodeproj -scheme FreeFlow -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
       xcodebuild -project FreeFlowCatalyst.xcodeproj -scheme FreeFlowMac -destination 'generic/platform=macOS,variant=Mac Catalyst' CODE_SIGNING_ALLOWED=NO build

On a device, the keyboard needs Allow Full Access to talk to the app through the App Group. On the Mac, the app asks for the microphone and for Accessibility (to see the fn key and paste at your cursor).

`scripts/release.sh` and `scripts/mac-release.sh` archive, sign, notarize and package releases. They read the App Store Connect key from `Configuration/release.env` (copy `release.env.template`) and the signing identity from a keychain you name; none of that is in the repository.

## Speech models

Free Flow downloads the model you pick from Hugging Face and checks it against the revision pinned in `App/Resources/model-manifest.json`. Each model keeps its own licence, stated here as its repository card states it.

| Model | Maker | Languages | Runs with | Licence as stated upstream |
|---|---|---|---|---|
| Parakeet Ultra (default) | Moondream, a post-training of NVIDIA Parakeet TDT 0.6B v3; Core ML conversion by FluidInference | 25 European languages | FluidAudio, Core ML | CC-BY-4.0 |
| Phonon-2 | Fermion Research, a re-training of NVIDIA Parakeet TDT 0.6B v3; Core ML conversion by FluidInference | English | FluidAudio, Core ML | CC-BY-4.0 |
| Parakeet Redux | Moondream, a ternary re-training of NVIDIA Parakeet TDT 0.6B v3; Core ML conversion by FluidInference | 25 European languages | FluidAudio, Core ML | CC-BY-4.0 |
| Bark 3.0 Clean | Conway Research (Underdog Bark 3.0 Clean), from NVIDIA Parakeet TDT 0.6B v3 and Moondream's Parakeet Ultra; Core ML conversion by FluidInference | English | FluidAudio, Core ML | CC-BY-4.0 |
| Bark 3.0 Pro | Conway Research (Underdog Bark 3.0 Pro), from NVIDIA Parakeet TDT 0.6B v3 and Moondream's Parakeet Ultra; Core ML files from the maker's repository | English | FluidAudio, Core ML | CC-BY-4.0 |
| Parakeet TDT 0.6B v3 Q4_0, Q4_K, Q8_0 (GGUF) | NVIDIA; GGUF files by ggml-org | 25 European languages | C++ engine | Weights CC-BY-4.0; ggml-org repository card MIT |

The notice files that ship with the Bark models are in `ThirdParty/Models`. The catalog itself is `Packages/FreeFlowKit/Sources/FreeFlowKit/Resources/speech-models.json`; the app, the setup picker and Settings > Models render whatever is listed there.

Text cleanup uses Apple Intelligence (Apple's on-device model through FoundationModels) when it is available and turned on (it is off until you turn it on); otherwise the recognizer's text goes in as heard. The disfluency tagger in `Packages/FreeFlowTagger` is a small Core ML token classifier that runs on the device.

## Privacy

Audio is turned into text on your device by the model you downloaded. While you dictate, the audio is written to the app's own private folder so an interruption does not lose it. The last finished dictation's audio stays for ten minutes, or until the next dictation, so you can retry it; then it is deleted. History and the dictionary stay on the device. Free Flow never sends your audio, your text or anything it keeps. The privacy policy is at https://mashbox.gg/freeflow/privacy.
